# 厂端录音复盘：质检规则跨场景统计开发交接

## 1. 需求背景

厂端看板“录音复盘”需要查看每一条规则的表现，并与顶部业务场景、组织、品牌、车型和时间筛选联动。SOP 质检分析、优势项识别、缺陷项识别、风险命中分析四个页签统一使用同一套场景展示和统计规则。

当前业务关系：

- 云外呼录音包含：首触跟进、邀约进店、排程确认。
- 门店工牌录音包含：进店接待、试乘试驾。
- 当前云外呼三个场景使用相同的 SOP 规则。
- 进店接待与试乘试驾使用不同的 SOP 规则。
- 未来云外呼三个场景也可能出现规则差异。

本次设计不增加规则范围卡片。四个页签的现有规则列表直接展示当前筛选范围内的规则合集。

## 2. 已确认的核心原则

### 2.1 规则是否合并，只看规则唯一编号

- 同一规则编号、同一判断标准：允许跨所选场景汇总。
- 不同规则编号：必须展示为两条规则。
- 即使规则名称相同，只要判断标准不同，也必须使用不同规则编号并展示为两条。
- 前端禁止通过规则名称判断两条规则是否相同。

示例：

| 规则编号 | 规则名称 | 判断标准 | 适用场景 | 展示方式 |
|---|---|---|---|---|
| `reception-needs-confirm` | 需求确认 | 判断门店接待中的需求探询是否完整 | 进店接待 | 独立一条 |
| `test-drive-needs-confirm` | 需求确认 | 判断试驾前是否确认客户试驾诉求 | 试乘试驾 | 独立一条 |

以上两条名称相同，但含义和判断标准不同，因此不能合并。

### 2.2 顶部筛选决定规则合集和统计样本

规则列表只展示与当前所选业务场景存在绑定关系的规则。

- 选择首触跟进：只展示适用于首触跟进的规则。
- 选择首触跟进、邀约进店：展示两个场景的规则合集。
- 选择云外呼三个场景：共用规则按三个场景汇总，独有规则单独展示。
- 选择进店接待、试乘试驾：展示两套规则的合集，不强制合并。
- 选择全部五个场景：展示五个场景对应的全部规则合集。

组织、品牌、车型和时间筛选只改变统计样本，不改变规则本身与业务场景的绑定关系。

### 2.3 每条规则独立计算命中率

对每一个 `rule_id`：

```text
样本数 = 当前筛选范围内，适用并执行了该规则的录音数
命中数 = 上述样本中，该规则判定为命中的录音数
命中率 = 命中数 ÷ 样本数
```

当同一规则编号适用于多个已选场景时：

```text
汇总命中数 = 各适用场景命中数之和
汇总样本数 = 各适用场景样本数之和
汇总命中率 = 汇总命中数 ÷ 汇总样本数
```

禁止采用“各场景命中率直接取平均”的计算方式。

### 2.4 四个分析页签统一执行

- SOP 质检分析、优势项识别、缺陷项识别、风险命中分析都必须配置规则与业务场景的绑定关系。
- 四个页签都根据顶部已选业务场景过滤规则、展示场景标签并汇总统计样本。
- “需求洞察、产品表达、服务红线”等属于规则分类，不再代替业务场景标签展示。

## 3. 页面展示要求

### 3.1 规则列表

保持原来的四列结构，不单独增加“适用场景”列：

| 规则项 | 命中率 | 命中/样本 | 操作 |
|---|---:|---:|---|
| 对比车型 `首触跟进` `邀约进店` `排程确认` | 78% | 1001/1280 | 看组织表现 |
| 需求确认 `进店接待` | 81% | 697/860 | 看组织表现 |
| 需求确认 `试乘试驾` | 76% | 410/540 | 看组织表现 |

展示约束：

- 规则名称后的蓝色标签表示该规则在当前筛选范围内适用的业务场景。
- 标签只能使用顶部已有的五个业务场景：首触跟进、邀约进店、排程确认、进店接待、试乘试驾。
- 同一规则适用于多个已选场景时，规则名称后依次展示多个标签；例如云外呼共用规则展示三个标签。
- 标签展示规则全部适用场景与顶部当前所选场景的交集；顶部取消某个场景后，对应标签和统计样本同时移除。
- 搜索同时匹配规则名称和业务场景标签。
- 原有命中率、命中数量、样本数量排序和分页保持不变。
- SOP 质检分析、优势项识别、缺陷项识别、风险命中分析都采用以上展示方式。

### 3.2 组织表现下钻

点击“看组织表现”后：

- 组织命中率、命中数和样本数必须沿用顶部当前所选业务场景与规则绑定范围的交集。
- 不允许把该规则不适用的场景录音计入组织样本。
- 建议后端返回样本是否充足；样本不足的组织需要标记，避免小样本命中率误导排序。

建议的最小有效样本门槛由业务另行配置，不在前端写死。

## 4. 推荐数据模型

### 4.1 质检规则主表

```text
quality_rule
```

| 字段 | 说明 |
|---|---|
| `rule_id` | 规则唯一编号，跨场景汇总的唯一依据 |
| `rule_name` | 规则名称，允许重名 |
| `analysis_type` | `sop`、`advantage`、`defect` 或 `risk` |
| `category_code` | 规则分类编号，不作为业务场景标签 |
| `category_name` | 规则分类名称，不作为业务场景标签 |
| `judgement_definition` | 判断标准说明 |
| `rule_version` | 规则版本 |
| `status` | 启用、停用 |
| `effective_start_at` | 生效时间 |
| `effective_end_at` | 失效时间 |

处理约定：

- 判断含义不同：创建新的 `rule_id`。
- 同一规则仅调整算法、提示词或阈值：保留 `rule_id`，升级 `rule_version`。
- 历史统计必须使用录音质检时实际生效的规则版本。

### 4.2 规则与场景绑定表

```text
sop_rule_scene_binding
```

| 字段 | 说明 |
|---|---|
| `rule_id` | 规则唯一编号 |
| `rule_version` | 规则版本 |
| `source_code` | `cloud` 或 `badge` |
| `scene_code` | 业务场景编号 |
| `enabled` | 是否启用 |
| `effective_start_at` | 绑定生效时间 |
| `effective_end_at` | 绑定失效时间 |

### 4.3 单条录音规则判定结果

```text
sop_rule_evaluation
```

| 字段 | 说明 |
|---|---|
| `recording_id` | 录音编号 |
| `rule_id` | 规则唯一编号 |
| `rule_version` | 本次质检使用的规则版本 |
| `source_code` | 录音来源 |
| `scene_code` | 业务场景 |
| `org_id` | 录音所属组织 |
| `is_applicable` | 本条录音是否适用该规则 |
| `is_hit` | 是否命中 |
| `evaluated_at` | 质检时间 |

统计样本只包含 `is_applicable = true` 的记录。

### 5.1 规则表现列表

```http

```

请求示例：

```json
{
  "analysis_type": "sop",
  "source": "all",
  "scene_codes": [
    "first_follow",
    "invite_store",
    "schedule_confirm",
    "store_reception",
    "test_drive"
  ],
  "org_path": [],
  "brand": "传祺",
  "model": "all",
  "start_date": "2026-07-30",
  "end_date": "2026-07-30",
  "keyword": "",
  "sort": "rate_desc",
  "page": 1,
  "page_size": 10
}
```

响应示例：

```json
{
  "total": 34,
  "items": [
    {
      "rule_id": "sop-compare-model",
      "rule_version": "1.0",
      "rule_name": "对比车型",
      "category_name": "需求确认",
      "applicable_scenes": [
        {
          "scene_code": "first_follow",
          "scene_name": "首触跟进"
        },
        {
          "scene_code": "invite_store",
          "scene_name": "邀约进店"
        },
        {
          "scene_code": "schedule_confirm",

      "hit_count": 1001,
```

说明：

- `category_name` 是规则分类，不作为 SOP 列表中的蓝色业务场景标签。

### 5.2 单规则组织表现

```http
POST /api/factory-dashboard/sop-rule-org-performance
```

请求必须包含：

- `rule_id`
- `rule_version` 或统计时间范围
- 当前顶部全部筛选条件
- 当前规则与所选场景的交集
- 当前组织层级

响应需返回：

- 组织编号和名称
- 组织层级
- 命中数
- 样本数
- 命中率
- 是否达到最小有效样本
- 是否支持继续下钻

## 6. 异常与边界处理

- 未选择任何业务场景：保持当前合法筛选回退逻辑，不发起空场景统计。
- 所选场景没有规则：按当前页签显示对应空状态，如“当前筛选范围暂无适用规则”。
- 规则样本数为 0：命中率显示 `--`，不得显示为 `0%`。
- 同名不同编号：允许同时出现在列表中。
- 同编号跨多个场景：返回一条汇总结果。
- 同编号不同版本：按录音实际使用版本统计；如需要跨版本查看，后端需明确版本合并策略。
- 场景被取消选择：立即从规则合集和统计样本中移除。
- 从规则列表进入组织下钻后修改顶部筛选：如果规则不再适用，应自动返回规则列表。

## 8. 验收标准

1. 默认选择全部五个场景时，列表同时包含云外呼、进店接待和试乘试驾规则。
2. 云外呼共用规则只展示一条，规则名称后显示“首触跟进、邀约进店、排程确认”三个标签。
3. 云外呼只选择一个或两个场景时，共用规则的场景标签、命中数、样本数和命中率同步变化。
4. 只选择工牌来源时，不展示云外呼规则。
5. 进店接待和试乘试驾的同名“需求确认”展示为两条，规则编号不同，蓝色标签分别显示“进店接待”和“试乘试驾”。
6. 取消某个场景后，该场景独有规则立即消失。
7. 点击规则查看组织表现时，统计样本沿用顶部当前所选业务场景与规则绑定范围的交集。
8. 搜索、排序、分页和组织下钻功能保持可用。
9. 页面在 1440px 常用桌面宽度下无横向溢出，规则名称和多个蓝色业务场景标签可完整查看。
10. 正式接口统计结果符合“总命中数 ÷ 总适用样本数”，不使用场景命中率平均值。
11. 优势项、缺陷项、风险项页签与 SOP 页签使用相同的五场景标签、筛选和汇总规则，不再显示规则分类标签代替业务场景。
